Philosophy & key decisions
The choices made here determine everything else. Most boilerplates fail because they accumulate defaults. These are deliberate decisions with explicit reasoning you can override.

Core philosophy

Configure, don't rewrite
Every module has a clear interface. Swap Stripe for Paddle, S3 for R2, Resend for Postmark — without touching business logic.
Thin layers, fat contracts
Router → Service → Repository. Each layer has a single job. Services never touch the DB. Repositories never know about HTTP.
Org-scoped from day one
Every table has org_id. Every repository query is scoped. This cannot be retrofitted cheaply — it must be designed in from the first migration.
Cursor pagination everywhere
Offset pagination silently breaks at scale. Cursor-based is the only acceptable default for a production template.
OpenAPI is the contract
Types flow from FastAPI → OpenAPI schema → generated TS client. No hand-written fetch calls. No type drift between frontend and backend.
Immutability where it matters
Audit log, billing events, webhook receipts — written once, never updated. Append-only tables for anything compliance-sensitive.

Backend
Architecture layers
The layer discipline is non-negotiable. It's what makes the template actually reusable. If a service imports from a router, or a router touches the DB, the architecture has broken.

The four-layer rule

1. Router
Handles HTTP only. Validates input (Pydantic). Calls service. Returns response schema. No business logic. No DB calls.
2. Service
Business logic lives here. Calls repositories. Calls other services. Emits events. Sends notifications. No HTTP, no DB queries.
3. Repository
All DB access. Always org-scoped. Returns domain models. No business logic. No HTTP concerns. Testable in isolation.
4. Model
SQLModel table class. Data shape only. No methods beyond simple validators. One file per domain entity.

Base classes

# app/db/base.py — BaseCRUD every repository inherits
class BaseRepository[T](Generic[T]):
    model: type[T]

    def __init__(self, session: AsyncSession, org_id: UUID):
        self.session = session
        self.org_id = org_id  # injected — all queries use this

    async def get(self, id: UUID) -> T | None:
        return await self.session.get(
            self.model, id,
            options=[selectinload("*")]
        )

    async def list_cursor(
        self, after: UUID | None, limit: int = 20
    ) -> list[T]:
        # cursor pagination — never offset
        q = select(self.model).where(
            self.model.org_id == self.org_id
        ).order_by(self.model.created_at.desc(), self.model.id.desc())
        if after:
            q = q.where(self.model.id < after)
        return (await self.session.exec(q.limit(limit))).all()

    async def create(self, data: dict) -> T:
        obj = self.model(org_id=self.org_id, **data)
        self.session.add(obj)
        await self.session.flush()
        return obj

Never omit org_id from a table

Every user-data table needs org_id. The repository's __init__ takes org_id and every query uses it. This is the multi-tenancy guarantee. Tables that belong to users directly (Session, OAuthAccount) use user_id as the scope instead.

Backend
Auth & sessions
Hand-rolled, not library-dependent. ~300 lines of code that you fully understand and can extend without fighting an abstraction.

Token strategy

Access token — 15 min JWT
Short-lived, stateless. Signed with RS256 (asymmetric — public key can be shared). Contains user_id, org_id, permissions snapshot.
Refresh token — 30 day, rotating
Stored as httpOnly Secure SameSite=Strict cookie. Hashed in DB. Rotation on every use — theft detection built in.
Session table
Every refresh token maps to a Session row with device, IP, last_seen. Users can see and revoke individual devices.

Backend
Multi-tenancy
The template starts with row-level tenancy (org_id on every table, every query scoped). Schema-level tenancy can be layered on top later without redesigning the data model.

What's built in Phase 1

  • ✓ Organization model with slug, settings JSONB, logo, plan reference
  • ✓ Membership table: user ↔ org with role
  • ✓ Signed invitation tokens (email → token → join → membership row)
  • ✓ Current org injected via middleware after auth (X-Org-ID header)
  • ✓ BaseRepository always scopes to org_id — impossible to forget
  • ✓ Settings page: org name, logo upload, member list, invite flow, role management
  • ✓ Feature flags: OrgFeatureFlag table keyed by (org_id, flag_name)

Invitation flow

POST /orgs/{id}/invitations  →  create Invitation row (email, role, token=sign(email+org+role), expires 72h)
                              →  send invite email with link
GET  /invitations/{token}/accept  →  verify signature + expiry
                                  →  create/link user account
                                  →  create Membership row
                                  →  delete Invitation row
Schema-level tenancy (future)

If you need strong tenant isolation later (regulatory, enterprise), the path is: create a Postgres schema per org, set search_path in the session middleware, move tables without org_id. The repository pattern makes this migration surgical — you only touch the session setup, not every query.

Webhook handler pattern

# POST /billing/webhooks/stripe
async def stripe_webhook(request: Request, session: AsyncSession):
    payload = await request.body()
    sig = request.headers.get("stripe-signature")
    event = stripe.Webhook.construct_event(payload, sig, settings.STRIPE_WEBHOOK_SECRET)

    # idempotency check — never process twice
    existing = await session.get(WebhookEvent, event["id"])
    if existing?.processed_at: return {"ok": True}

    # store raw event first, then process
    stored = WebhookEvent(id=event["id"], type=event["type"], payload=event)
    session.add(stored)
    await billing_service.handle_event(event, session)
    stored.processed_at = utcnow()
    await session.commit()

Plan-gating dependency

# Use as a FastAPI dependency on any protected route
def require_feature(feature: str, minimum_value: int | None = None):
    async def checker(org: Organization = Depends(get_current_org)):
        value = org.plan.features.get(feature)
        if not value: raise HTTPException(402, "upgrade required")
        if minimum_value and value < minimum_value:
            raise HTTPException(402, "plan limit reached")
    return checker

# Usage:
@router.post("/reports", dependencies=[Depends(require_feature("advanced_reports"))])

File storage
Files never proxy through the API. Users upload directly to object storage via pre-signed URLs. The API only handles metadata.

Storage backend interface

class StorageBackend(Protocol):
    async def presign_upload(self, key: str, content_type: str, max_bytes: int) -> PresignedUpload: ...
    async def presign_download(self, key: str, expires: int = 3600) -> str: ...
    async def delete(self, key: str) -> None: ...
    async def exists(self, key: str) -> bool: ...

# Swap implementations via config:

# STORAGE_BACKEND=r2 → R2Backend (S3-compatible)

Upload flow

1. POST /files/presign { filename, content_type, size }
   → validate size limit (from plan.features.storage_gb)
   → create StoredFile row (status=pending)
   → return { upload_url, file_id, fields }

2. Client PUTs directly to S3/R2 using upload_url

3. POST /files/{id}/confirm
   → verify file exists in storage
   → update StoredFile status=ready
   → enqueue virus_scan_job
   → return StoredFile metadata

# Every request gets a UUID, traced end-to-end
class RequestIDMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        request_id = request.headers.get("X-Request-ID", str(uuid4()))
        request.state.request_id = request_id
        response = await call_next(request)
        response.headers["X-Request-ID"] = request_id
        return response

Testing strategy
Tests are the contract that lets you change code without fear — the single most important enabler of "ship a new idea in days". The strategy is a pyramid: many fast unit tests, fewer integration tests, a handful of E2E tests that cover the money paths.

The test pyramid

Unit — fast, many
Services and pure functions tested in isolation. Repositories mocked. Milliseconds each. Run on every save. This is where most tests live.
Integration — real DB
API endpoints tested against a real Postgres + Redis (testcontainers). Verifies routing, auth, serialization, and queries together.
E2E — few, critical
Playwright (web) and Maestro (mobile) drive the real UI through signup → invite → upgrade. Slow, so reserved for flows that must never break.
Contract — auto-generated
Schemathesis fuzzes every endpoint against the OpenAPI schema. Free property-based testing the moment a route exists.

Beyond the Top 10

Because this is an API-first product, the template also tracks the OWASP API Security Top 10 — particularly excessive data exposure (response schemas never leak fields the caller shouldn't see), broken object-property-level authorization (mass-assignment guarded by separate request schemas), and unrestricted resource consumption (pagination limits capped, upload sizes bounded by plan). The OWASP ASVS Level 2 checklist serves as the pre-launch verification standard for any product built on the template.

Penetration testing before real money

Automated scans catch the known classes. Before processing live payments or handling sensitive customer data, commission a manual pentest. The automation gets you to a defensible baseline; a human finds the logic flaws scanners can't.

Migrations are the one-way door

Code rolls back instantly; data does not. Every migration must be reversible and backward-compatible with the currently-running code (expand-then-contract: add column, deploy, backfill, switch reads, drop old column in a later release). A migration that breaks the running version causes downtime during the rollout window.

Best practices
The conventions that keep a codebase fast, secure, and maintainable as it grows and as new ideas get built on top of it. These aren't aspirations — they're enforced by the tooling and CI already described, so they hold even under deadline pressure.

Code quality & consistency

PracticeHow it's enforced

Strict typing everywheremypy --strict, tsc strict. any and untyped functions fail the build. Types are documentation that can't drift.

Architecture discipline

Dependency direction is one-way
router → service → repository → model. Enforced with import-linter: a service importing a router fails CI. The arrows never reverse.
Modules are self-contained
A feature module owns its models, schemas, service, router. Cross-module calls go through services, never by reaching into another module's repository.
Composition over inheritance
BaseRepository is the one inheritance point. Everything else composes via dependency injection — easy to test, easy to swap.
Explicit over implicit
No magic globals, no hidden side effects. org_id is passed in, not pulled from thread-local. You can always trace where a value came from.

    status_code = 404; code = "not_found"

class PermissionDeniedError(DomainError):
    status_code = 403; code = "permission_denied"

class PlanLimitError(DomainError):
    status_code = 402; code = "plan_limit_reached"

# One exception handler maps every DomainError to the standard envelope.
# Services raise meaning ("PlanLimitError"), not HTTP ("HTTPException(402)").
# The router layer owns the HTTP translation — keeps services framework-free.

The rules: never swallow an exception silently, never catch bare Exception except at the top-level handler, and always raise a typed domain error that carries enough context to debug from the log line alone. User-facing messages are actionable and blame the situation, not the user.

Database best practices

RuleWhy
Every migration is reversibledowngrade() actually works. Tested in CI by migrating up, down, up again.
Expand-then-contract schema changesAdd new, deploy, backfill, switch, remove old — never a breaking change in one step. Enables zero-downtime deploys.
Index every foreign key + filter columnorg_id, user_id, created_at, status — anything in a WHERE or ORDER BY. Missing indexes are the #1 cause of slow SaaS.
No business logic in migrationsData backfills run as idempotent jobs, not in the schema migration. Migrations stay fast and reversible.
N+1 caught in testsA query-count assertion fixture fails tests that issue unexpected queries. selectinload is explicit, never accidental.
Timestamps + soft delete on everythingcreated_at, updated_at, deleted_at as a base mixin. You always know when and whether a row is live.

API design

  • Versioned from day one (/api/v1/) — breaking changes get a new version, never a silent break
  • Consistent envelope ({ data, error, meta }) — clients handle one shape, always
  • Cursor pagination on every list — no exceptions, no offset
  • Request schemas separate from models — prevents mass assignment, decouples wire format from storage
  • Idempotency keys on every mutating external call (Stripe, email) — safe to retry
  • Deprecation policy: a field/endpoint is marked deprecated in OpenAPI for one minor version before removal

Documentation & decisions

ADRs (Architecture Decision Records)
docs/adr/ holds short, dated records of every significant choice and its reasoning. Future-you (and new hires) learn why, not just what.
README per module
Each module has a README: what it does, its public service interface, its events. The _template includes the skeleton.
Self-documenting API
OpenAPI is generated from code with descriptions on every field. The docs can't go stale because they are the code.
Runbooks
docs/runbooks/ for operational tasks: rotate a key, replay a webhook, restore a backup. Written before you need them at 3am.

Dependency hygiene

  • Every dependency is a liability — add one only when it clearly beats writing the code yourself
  • Lockfiles committed (pnpm-lock.yaml, uv.lock); exact versions, reproducible builds
  • Renovate/Dependabot opens grouped update PRs weekly; CI decides if they're safe
  • Prefer the standard library and the framework's built-ins before reaching for a package
  • Audit transitive dependencies — a small package can pull in a large, risky tree

Observability discipline

  • Structured logs only — every line is JSON with request_id, user_id, org_id
  • Never log secrets, tokens, passwords, or full PII — a log scrubber strips known-sensitive keys
  • Log levels mean something: ERROR pages someone, WARN is reviewed, INFO is the audit trail, DEBUG is local-only
  • Every external call (DB, Stripe, email) is traced — you can see where latency goes
  • Alerts are actionable: an alert that fires without a clear response gets deleted or fixed
The maintainability test

The real measure of these practices: can a developer who has never seen the codebase add a correct, tested, secure feature in their first week? If the answer is yes, the template is doing its job — and every new product idea you build on it inherits that same speed.

The feature creep trap

Phase 1 acceptance criteria: a new user can sign up, verify their email, invite a team member, and upgrade to a paid plan. That's it. If that works end-to-end with tests, Phase 1 is done. Not "mostly done".

Workflow
Launch checklist
Run this before every production launch. Not after the first bug report.

Security

  • All secrets in environment variables, none in code or git history (truffleHog scan clean)
  • HTTPS enforced, HSTS header present
  • CORS restricted to known origins
  • CSP header configured and tested
  • Rate limiting active on all auth endpoints
  • pip-audit and npm audit both pass (no high severity CVEs)
  • Stripe webhook signature verification active
  • JWT private key rotated from the default
  • Sentry configured and receiving test events

Data

  • All Alembic migrations applied to production DB
  • DB backups configured and tested (restore drill done)
  • Soft-delete verified: deleted records not returned in API responses
  • /me/export produces a complete, accurate zip
  • /me/delete tested end-to-end including purge job
  • org_id present and indexed on every user-data table

Reliability

  • /health/ready returns 200 from a fresh container
  • ARQ worker starts clean and processes a test job
  • Stripe webhook delivery confirmed in Stripe dashboard
  • Email delivery confirmed via test send
  • DB connection pool not exhausted under load (check Prometheus)
  • Redis memory limits set (no silent OOM)

Testing & QA

  • Coverage gates pass: 85% overall, 100% on auth/billing/tenancy
